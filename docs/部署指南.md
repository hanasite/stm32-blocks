# 部署指南（人话版）

「STM32 积木工坊」核心依赖其实只有两样：**Node.js**（跑本地网页服务）和 **STM32CubeCLT**（编译器 + 烧录器 + 调试器的全家桶，约 2.3GB）。按你的场景挑一条：

---

## 场景 A：自己的笔记本，现场直连模式 ⭐ 推荐

不用 VSCode，网页里点两个按钮就编译烧录。装三样：

### 1. STM32CubeCLT（编译器全家桶）

三个渠道任选其一：

| 渠道 | 说明 |
|---|---|
| **FubeMX（波特律动）** | [fubemx.keysking.com](https://fubemx.keysking.com) —— 国内直连速度快，能下载 STM32CubeMX / **STM32CubeCLT**；装完启动器一路 Next 即可 |
| ST 官网 | 搜 "STM32CubeCLT" 下载 Windows 64-bit 安装包（需注册 ST 账号，国内下载较慢） |
| 找学长要 | `STM32CubeCLT_1.18.0` 整个文件夹拷贝即可（便携 U 盘版里自带一份） |

安装默认路径是 `D:\STM32CubeCLT_1.18.0`。装到别处也行——设一个环境变量 `CUBECLT` 指向你的安装目录，所有脚本都会认它。

### 2. Node.js（LTS 版）

[nodejs.org](https://nodejs.org) 下载 LTS，一路 Next。或者直接用便携版：把便携 U 盘里 `env\node` 文件夹拷出来即可用。

### 3. ST-Link 驱动（一次性）

插上 ST-Link，Windows 通常会自动装好驱动；装不上就去 ST 官网下 ST-Link 驱动。

**然后就能用了**：双击仓库根目录的 **`启动本地编译服务.bat`** → 浏览器自动打开 → 拼积木 → 「🔨 编译」→ 插好 ST-Link 点「⚡ 编译并烧录」。编译产物在 `local-builds/<工程名>/`。

不需要联网（网页里所有东西都是本地的）。

---

## 场景 B：别人的电脑，下载 zip + VSCode 模式

给没有这套工具的同学：

1. 装 **STM32CubeCLT**（渠道同上）
2. 装 **VSCode** + 扩展 **cortex-debug**（发布者 marus25）
3. 网页里拼积木 → 「⬇ 下载完整工程」→ 解压 → VSCode 打开文件夹 → 按 F5

⚠️ 注意：模板 `.vscode/` 配置里写死了 `D:\STM32CubeCLT_1.18.0` 路径——装到同一路径最省事；装别处的话要改 `template\.vscode\launch.json` 等文件里的路径（或者干脆用场景 A 的直连模式，不碰 VSCode）。

---

## 场景 C：零安装，便携 U 盘 ⭐ 最省事

拿到「STM32 积木工坊便携版」U 盘（约 2.5GB）：

1. 插上 U 盘，双击 **`启动本地编译服务-便携.bat`**
2. 完事了——Node 和 CubeCLT 都在 `env\` 里，插到任何 Windows 电脑直接跑，盘符变了也不受影响

唯一带不走的是 **ST-Link 驱动**（系统级），目标电脑第一次用 ST-Link 时 Windows 一般会自动装。

### 怎么自己制作/更新 U 盘版

在装好环境的机器上，**双击仓库根目录的 `制作便携U盘.bat`**（会提示输入目标目录，如 `H:\stm32blocks`），或者命令行：

```
node tools/make-portable.js H:\stm32blocks
```

脚本自动完成：同步仓库 → 下载便携 Node（版本跟随当前机器）→ 从 `CUBECLT`（默认 `D:\STM32CubeCLT_1.18.0`）拷贝 CubeCLT → 生成便携启动器和说明文件。**重复运行 = 增量更新**（已有 Node/CubeCLT 自动跳过，仓库部分做镜像同步），所以代码更新后重新跑一次即可。加 `--refresh-clt` 可强制重拷 CubeCLT。

## 场景 D：Docker / NAS 远程编译（产物下载到电脑烧录）

没有 Windows 环境、或想把编译放服务器上：

```bash
# 在装有 Docker 的 Linux 机器（也可是 NAS）上：
cd stm32-blocks
docker compose up -d --build
```

镜像里封装了 Linux 原生工具链（`gcc-arm-none-eabi + cmake + ninja`，约 500MB，**不需要** CubeCLT 和 ST-Link 驱动）。之后浏览器打开 `http://<机器IP>:8899`：

- 「🔨 编译」在容器里执行；成功后弹窗出现 **「⬇ 下载 .hex / .bin」**
- 容器里没有 ST-Link，「编译并烧录」按钮自动隐藏
- 把 hex 下载到接好 ST-Link 的电脑，用 **STM32CubeProgrammer** 烧：图形界面选 hex → Download；或命令行
  `STM32_Programmer_CLI -c port=SWD -w xxx.hex -v -rst`，再补一条 `STM32_Programmer_CLI -c port=SWD -run`（不加 `-run` 内核会停在 halt 状态）

维护：`docker compose logs -f` 看日志；`docker compose up -d --build` 拉取代码更新后重建；产物持久化在仓库目录的 `local-builds/`。

## 怎么确认装好了

| 检查 | 方法 | 正常表现 |
|---|---|---|
| CubeCLT | 文件管理器看一眼 | `D:\STM32CubeCLT_1.18.0\GNU-tools-for-STM32\bin\arm-none-eabi-gcc.exe` 存在 |
| Node | 命令行 `node --version` | 输出 `v18` 以上（如 v24.x） |
| 整体 | 双击 `启动本地编译服务.bat` | 页头出现绿色徽标「本地工具链已连接」 |
| 编译器 | 页面上随便点一下「🔨 编译」 | 几秒后弹窗「✅ 编译成功」 |

## 常见坑（都是真踩过的）

- **克隆版 ST-Link**：烧录一般能用；但 VSCode 调试（F5）需要新固件（V2J48 以上），旧固件 gdbserver 会拒服务。
- **工程可以放中文文件夹**：构建脚本会自动规避 cmake 在中文路径下的已知崩溃，但能放英文路径更省心。
- **旧启动脚本报"找不到节点"**：那是用系统 Node 的 `启动本地编译服务.bat`——没装 Node 就用便携版那个 bat。
- **改动模板后网页没变化**：跑了 `node tools/embed-template.js` 吗？（模板是内嵌进网页的，改了要重嵌）
- **舵机要接 5V**、其他模块 3V3——详细接线点网页里的「❓ 接线帮助」。
